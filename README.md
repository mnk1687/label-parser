# Label Studio · 批次标签工作台 v0.3

整批导入 PDF，自动找到 ProdSheet 的 TXT1 款号与条码关系，识别 MAIN / CARE / COMPO 标签。按款号查看文件关联链，勾选需要的款号和来源文件，再分别导出 PDF。

## 新版操作

关闭旧窗口，双击 `启动解析工具.command`。

1. 点击 **导入整批 PDF**，一次选中 ProdSheet 与本批次所有标签文件；也可点击 **导入批次文件夹**，导入一个批次或包含多个批次子文件夹的目录。
2. 程序按文件名区分 ProdSheet、MAIN、CARE、COMPO，自动读取生产单并扫描文件。
3. 在 **勾选款号** 页签点击一个款号查看结果，点击首列的 ☐ / ☑ 选择是否导出。**默认不勾选款号**，不会自动导出全部款号。
4. 在 **勾选文件** 页签勾选需要的来源文件。默认文件全选；可以只保留 MAIN、CARE 或任意文件。文件和款号取交集。
5. 中间选择标签，右侧查看 **标签预览** 或 **文件关联链**。关联链列出完整文件名、页码、Barcode 以及 ProdSheet 的对应行。
6. 点击 **查看导出清单**，确认将生成的独立 PDF、包含款号与页数，然后选择保存位置。

点击行用于查看，点击首列复选框或按空格切换导出选择。勾选动作不会重新扫描文件。

## 导出不会混在一起

- 默认 **按批次 + 文件分开**：勾选款号 A、B 和 MAIN、CARE，生成该批次的 MAIN 汇总与 CARE 汇总两个 PDF，各包含 A、B 的对应内容。
- 可选择 **按批次 + 款号 + 文件分开**：上述选择生成 A-MAIN、A-CARE、B-MAIN、B-CARE 四个 PDF。
- 不同批次始终独立。同一类型的不同源文件也不会合并。
- 未命中的组合不生成空 PDF；以导出清单中实际列出的文件为准。
- 每次导出建立独立时间戳子目录，文件名包含批次、源文件、款号或款号数量、唯一标识；不会覆盖此前输出。
- 只生成 PDF，**不生成 JSON**。每个标签一页，附款号书签。
- 默认 300 DPI，可改为 200 或 400 DPI。输出保持实际裁切范围，仍为图片型 PDF，不保留裁切外隐藏内容。

例如本批次勾选 `FBL015-166-03` 和 MAIN、CARE，导出两个独立 PDF，各 7 页。

## 关联依据可追溯

示例关联链：

```text
目标款号 FBL015-166-03
ProdSheet_2453475-CARELABEL_2.pdf 第 1 页第 1 条：
TXT1 = FBL015-166-03，Barcode = 5208133300829

MAIN 文件第 1 页按款号直接匹配，标签 Barcode = 5208133300829
根据相同 Barcode，再关联到 CARE / COMPO1 / COMPO2 / COMPO3 的具体文件及页码。
```

OCR 读码与 PDF 文本读码分别注明。没有直接匹配的 MAIN 时，会明确说明关联依据来自 ProdSheet，不虚构 MAIN 关联。生产单页内“第 N 条”指表格正文中第 N 条 TXT1 明细。

## 自动归组的边界

文件名识别角色；**同一个文件夹作为一个批次边界**。示例标签文件名没有 `ALT-SS27-016` 批次号，因此不能仅凭相同的 MAIN / CARE 等名称判断跨文件夹的归属。

- 一个批次文件夹需要且只能有一份可识别的 ProdSheet。
- 导入包含多个子文件夹的目录时，每个批次分别识别和导出。
- 同目录有多份 ProdSheet，或没有 ProdSheet，会报告无法唯一归组并跳过该目录，不猜测配对。将每批生产单和标签放入对应子文件夹即可。
- 同一次导入识别异常会在底部列出。此前已导入的其他批次仍保留在工作台，可用“当前批次”下拉菜单切换；它们的勾选状态也会保留，导出前以清单为准。

## 性能优化与验证

- 图片页的多个红色条码合并为一次 OCR，无法读取时回退到单标签识别。
- 每页 PDF 文本结构只读取一次，再从中提取标签区域。
- 成功结果保存在本机临时目录的 SQLite 缓存中。缓存键包含源文件完整 SHA256、目标款号、条码映射及算法版本，文件内容或规则改变后自动失效。缓存中有文档识别内容，仅本机使用；不是用户导出文件。临时目录被系统清理后会重新识别。
- 默认导出 300 DPI，勾选后的结果直接导出，不重做识别。

在本机对 ALT-SS27-016 进行实测（识别引擎时间，不含导出与界面操作）：5 个标签 PDF / 224 页 / 1950 个标签，首次约 **59.01 秒**，复用缓存约 **0.06 秒**。不同电脑、文件清晰度和页数会影响耗时。

本次仍核对到每份文件各 390 个唯一条码，与生产单的 390 条明细全部对应，32 个款号全部匹配。已测试自动分类、批次隔离、选择交集、独立导出、缓存复用与内容变更失效、关联来源说明、条码冲突和缺框告警。GUI 测试验证了两种窗口尺寸下操作按钮可见，以及一个款号 × 两个文件生成两个 PDF。

## 环境与原有命令行

当前 Mac 已准备好依赖。将源码移到其他位置后，启动脚本会创建本地 `.venv` 并安装依赖；需要 Python 3.10+（包含 Tkinter）及 Tesseract。文档不上传服务器。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m label_parser --gui
.venv/bin/python -m unittest discover -s tests -v
```

原来的 `--prodsheet / --keyword / --output` 命令行接口仍保留，用于明确指定的单个汇总 PDF。新版的勾选与分文件导出在桌面工作台中使用。

## 当前版式范围

适配本批次 ProdSheet TXT1 表格、青色边框标签和 13 位条码。没有青色边框、破损或倾斜图片、其他生产单表格需要适配。OCR 不做模糊猜码，异常项需检查。空白联或只有条码的标签按源稿保留。文件名归类不代替款号/条码内容验证。
